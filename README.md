# TermuxYoutube

Одно устанавливаемое **Android-приложение** (APK): десктопный YouTube в WebView,
свой редактор **My Mix** и загрузка/прослушивание **прямо внутри приложения**.
Без Termux, без локального сервера, без облака — весь yt-dlp работает в самом APK.

Качает **аудио в максимальном качестве** (чистый `m4a` с обложкой и тегами),
включая приватные плейлисты и динамические **My Mix**. Вход — импорт cookies из
настоящего браузера одним тапом (внутри приложения Google войти не даёт — см.
[«Болячки»](#болячки-youtube-и-как-они-решены)).

> **Было → стало.** Раньше проект жил в Termux (терминальный TUI + Web-UI на
> `127.0.0.1`, установка ~300 МБ). Теперь это **одно нативное приложение** —
> Termux, локальный веб-сервер и два интерфейса больше не нужны.

## Что умеет

- **YouTube в WebView** — настоящий десктопный сайт. Поверх плавают кнопка
  «Скачать» (видна на видео/миксе/плейлисте) и иконка аккаунта; уезжают при
  прокрутке, чтобы не мешать.
- **Редактор My Mix** — выезжает листом снизу со скруглённым верхом и ручкой.
  Состав микса снимается **прямо со страницы** (а не повторной выдачей — она у
  динамического микса другая), свайп влево убирает трек, ручка справа — переставить.
- **Загрузка внутри APK** — yt-dlp (Python через Chaquopy), без ffmpeg: теги,
  номер трека и обложку пишет mutagen; файл кладётся в общую «Музыку» через
  MediaStore (плеер видит сразу). Фоновая загрузка с прогрессом и отменой.
- **Прослушивание без скачивания** — свой плеер: играет с выключенным экраном,
  управление на локскрине и в Now Bar (обложка, вперёд/назад/пауза).
- **100% on-device** — ничего не уходит на сторонний сервер.

## Болячки YouTube и как они решены

Самое интересное: за 2025–2026 YouTube выстроил несколько стен против качалок, и
каждую пришлось обойти — честно и локально, без внешних сервисов.

### 1. JS-челлендж (signature + nsig)
С 2025 YouTube отдаёт ссылку на поток только тому, кто **выполнит его
JavaScript**: расшифровать подпись и пересчитать параметр `n`. yt-dlp умеет это
лишь через внешний JS-движок (Deno/Node) — а внутри Android-приложения движка нет,
и запустить обычную программу песочница не даёт.
**Решение:** в APK вшит крошечный движок **QuickJS** (~0.8 МБ, собран под arm64).
yt-dlp передаёт ему головоломку, тот решает — всё в приложении. Без этого
извлечение не работает вообще.

### 2. Чистое аудио спрятано за PO-токеном (SABR)
Даже с решённым челленджем web-клиент отдаёт лишь комбинированный поток 360p
(видео+звук); чистая аудио-дорожка (`itag 140` m4a) спрятана за **PO-токеном**, а
сам web-клиент форсирован на SABR-протокол без прямых ссылок.
**Решение:** PO-токен куёт **BotGuard** (библиотека `bgutils-js`) прямо в нашем
WebView — там настоящий Chromium с десктопным UA и cookies, а это ровно то, что
BotGuard и проверяет. Токен отдаётся `mweb`-клиенту → получаем чистый `m4a`.
Токена нет или он протух — откат на 360p-поток (звук в нём тоже есть).

### 3. Вход в Google блокируется в WebView
Google метит встроенные браузеры и отказывает им во входе.
**Решение:** логина внутри приложения нет принципиально — **cookies импортируются**
из настоящего браузера одним тапом (расширение собирается самим приложением и
шлёт cookies назад по ссылке). Подменять клиента под проверку безопасности
отказались.

### 4. Фон — без платного Premium
Держать играющей саму веб-страницу YouTube с выключенным экраном — это обход
платного фонового режима.
**Решение:** страницу не трогаем — берём аудио-поток и играем **своим плеером**
(MediaPlayer + MediaSession + wake-lock). Это наше аудио и своя foreground-служба,
никаких «ворот» YouTube.

### 5. Без ffmpeg
ffmpeg — это десятки мегабайт в APK ради косметики (обложка, теги).
**Решение:** качаем уже готовый поток (перекодировать нечего), а обложку и теги
пишет **mutagen** прямо в контейнер m4a — это килобайты.

## Архитектура

Нативное приложение на **Kotlin / Jetpack Compose**; извлечение — **Python/yt-dlp
через Chaquopy**; JS-движок — **QuickJS**; плеер — **MediaPlayer + MediaSession**.

```
WebView (десктопный YouTube, логин по cookies)
   │  снимок состава My Mix прямо со страницы
   ▼
Редактор My Mix (Compose)
   ├── «Скачать» ─► DownloadService ─► grabber.py (yt-dlp) ─┐
   └── «Слушать» ─► PlaybackService (свой плеер, Now Bar)   │
                                                            ├─ QuickJS ...... JS-челлендж (sig/nsig)
                                                            ├─ PoToken (WebView) .. чистый m4a
                                                            └─ mutagen ........ теги + обложка
Готовый файл ─► общая «Музыка» (MediaStore)
```

- **`ui/`** (Compose): `WebScreen` (YouTube + плавающие кнопки), `MixEditor`
  (лист-редактор), `MiniPlayer` (нижний плеер), экран входа по cookies.
- **`data/`**: `Downloader`/`DownloadService` (загрузка), `PlaybackService`
  (плеер + очередь Now Bar), `CookieStore` (сессия), `PoToken` (BotGuard в WebView).
- **`python/`**: `grabber.py` (yt-dlp: probe / download / audio_url),
  `tagging.py` (mutagen).
- **native**: `libqjs.so` (QuickJS, распаковывается на диск и запускается).

## Сборка

Стек: Kotlin 2.0.21 · Jetpack Compose 1.7 · AGP 8.5 · Gradle 8.9 · compileSdk 34 ·
Chaquopy (Python 3.12, yt-dlp + mutagen). Только `arm64-v8a`.

```bash
gradle :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

Извлечение завязано на встроенный QuickJS (API 29+ на устройстве) и свежие пины
`yt-dlp` / `yt-dlp-ejs` / `bgutils-js` — если YouTube что-то поменяет, обновляются
в первую очередь именно они.

## Чего здесь нет (осознанно)

- **Видео/4K** — только звук.
- **Логин в Google внутри приложения** — это обход проверки Google; cookies берём
  из настоящего браузера.
- **Фоновое воспроизведение самой веб-страницы YouTube** — обход платного
  Premium; вместо этого свой плеер.
