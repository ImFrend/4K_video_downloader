



# TermuxYoutube

Аудио-граббер плейлистов YouTube для Android (проверено на **Samsung S23 Ultra**
и **Helio G88 / 4 ГБ**, aarch64), работает прямо в Termux. Качает **только аудио
в максимальном качестве**, включая **приватные плейлисты** и динамические
**My Mix** — cookies приезжают из браузера телефона одним тапом. Два интерфейса:
терминальный **TUI** и **Web-UI** в браузере телефона («как приложение», без
команд).

Установка — **~300 МБ и пара минут**, одно окружение. Своего браузера у проекта
нет: почему так и что было вместо — [«Чего здесь нет и почему»](#чего-здесь-нет-и-почему).

## Что это и чем не является



- ✅ Скачивает **аудио** из плейлистов/видео/My Mix в `m4a` (AAC) или `mp3`.
- ✅ Тянет **приватные плейлисты** и **My Mix** (cookies из браузера телефона —
  один тап по иконке расширения, без своего браузера в проекте).
- ✅ Встраивает **обложку** (cover art) + теги: `album`, `track=N/всего`
  (Samsung Music сортирует по тегу → правильный порядок 1..25, не по имени).
- ✅ **Дедуп**: один трек не качается дважды (по video id + архив `.downloaded.txt`).
- ✅ Имена файлов — строго **UTF-8** (NFC), любой язык сохраняется как есть.
- ✅ **Параллельные загрузки** с человеческим темпом (джиттер старта + паузы).
- ✅ Мгновенная индексация в медиатеку (`termux-media-scan`) — Samsung Music видит
  треки сразу, без перезагрузки телефона.
- ✅ Премиум-**TUI** (Textual) **и** премиум-**Web-UI** (iOS-стиль, AMOLED).
- ✅ **100% on-device**: web-сервер слушает только `127.0.0.1`, никакого облака.
- ❌ Не качает видео/4K (осознанно — только звук).
- ❌ Не отдельное Android-приложение (пока) — всё живёт в Termux.

## Требования (поставить ДО установки)

### 1. APK-приложения

Нужны 4 приложения. Три из них — Termux и его спутники — **из одного источника**
(F-Droid *или* GitHub-релизы). Смешивать нельзя: у них разные подписи, и
«соседние» приложения (API, Widget) просто не смогут общаться с Termux.

| APK | Зачем | Где взять |
|---|---|---|
| **Termux** | сам терминал | [F-Droid](https://f-droid.org/packages/com.termux/) |
| **Termux:API** | `termux-media-scan`, wake-lock, буфер обмена | [F-Droid](https://f-droid.org/packages/com.termux.api/) |
| **Termux:Widget** | иконка запуска на домашнем экране | [F-Droid](https://f-droid.org/packages/com.termux.widget/) |
| **Kiwi Browser** | *для приватных плейлистов*: держит расширения Chrome, отдаёт cookies качалке одним тапом | Google Play |

> ⚠️ Версия Termux из **Google Play устарела** и не обновляется — она не подойдёт.
> Termux:X11 больше не нужен вовсе.

### 2. Место и питание

- **~300 МБ свободно** — это вся установка целиком. Сама музыка — сверх этого.
- **Отключить оптимизацию батареи для Termux**:
  *Настройки → Приложения → Termux → Батарея → «Не оптимизировать / Unrestricted»*.
  Иначе Android (Doze) прибьёт долгую загрузку при гаснущем экране.
- Интернет на первом запуске нужен обязательно: yt-dlp докачивает решатель
  JS-challenge YouTube (см. «Риски»).

## Установка — одна команда

```bash
pkg install git -y
git clone https://github.com/ImFrend/4K_video_downloader.git
cd 4K_video_downloader
bash scripts/setup-termux.sh
```

> Репозиторий называется `4K_video_downloader` по историческим причинам — проект
> начинался как замена 4K Video Downloader и качал видео. Сейчас он качает только
> аудио и зовётся **TermuxYoutube**; папка и URL остались прежними, чтобы не
> ломать `git pull` у тех, кто уже поставил. Так и должно быть — это не опечатка.

Ставится ровно одно окружение — **пара минут, ~300 МБ**:

1. обновляет пакеты Termux;
2. ставит нативную часть (python, ffmpeg, git, termux-api, deno);
3. просит разрешение на память телефона (`termux-setup-storage`);
4. ставит Python-зависимости качалки (yt-dlp, textual, rich);
5. кладёт ярлык в `~/.shortcuts` для Termux:Widget.

**Приватные плейлисты и My Mix при этом работают** — cookies приезжают из
браузера телефона одним тапом (см. ниже).

Скрипт **идемпотентный**: если что-то отвалилось (сеть, место) — просто запусти
его ещё раз, уже поставленное переустанавливаться не будет.

### Что именно ставится (полный список зависимостей)

| Слой | Пакеты | Зачем |
|---|---|---|
| Termux, `pkg` | `python` `ffmpeg` `git` `termux-api` `python-pip` | ядро качалки, извлечение аудио, медиаскан |
| Termux, `pkg` | `deno` (либо `nodejs`, либо `quickjs-ng`) | JS-рантайм для n-challenge YouTube — **без него «Only images are available»** |
| Termux, `pip` | `yt-dlp` `textual` `rich` | загрузка, TUI |

Всё. Три строки — это весь список.

Про JS-рантайм, потому что тут легко потерять день: `deno` лежит в **главном**
репозитории Termux (`tur-repo` не нужен), но собран только под `aarch64` и
`x86_64` — на 32-битных `armv7` его там нет. Установщик поэтому пробует по
очереди `deno` → `nodejs` → `quickjs-ng`, а yt-dlp разрешено брать любой из них
(`config.JS_RUNTIMES`): по умолчанию он включает **только** `deno`, и без этой
настройки поставленный `nodejs` просто не использовался бы. Проверить, какой
выбран: `bash scripts/doctor.sh`.

Web-UI **зависимостей не имеет вообще** — он на stdlib (`http.server`). Auth
тоже: cookies присылает расширение браузера, а проверка сессии — один `GET`
через `urllib`.

## Использование

```bash
python main.py                 # TUI: вставь ссылку на плейлист → Enter
python main.py web             # Web-UI на localhost (браузер телефона)
python main.py kiwi            # собрать расширение для Kiwi (cookies одним тапом)
python main.py cookies         # взять cookies файлом-экспортом (если без расширения)
python main.py check           # жива ли сессия YouTube (один GET, без браузера)
python main.py doctor          # что стоит, чего не хватает и чем чинить
python main.py grab <URL>      # без интерфейса (отладка)
```

Две команды — обёртки над скриптами, а не отдельная реализация: `main.py doctor`
запускает `scripts/doctor.sh`, а `main.py check` — то же, что `python -m
auth.refresh`. Вызывай как удобнее, результат один и тот же.

Музыка сохраняется в `/storage/emulated/0/Music/<Плейлист>/NN - Название.m4a`
(путь задан в `config.OUTPUT_DIR`).

### My Mix: чей микс скачается — решают cookies

**RD-микс привязан к идентичности сессии в cookies.** Это оказалось ключом ко
всему; проверено на устройстве:

| проверка | результат |
|---|---|
| cookies от сессии, поднятой своим Chromium; клиенты `web`/`mweb`/`tv`/default | у всех **2 совпадения из 25** с браузером телефона |
| повтор того же запроса | список **тот же** — у каждой стороны своя устойчивая станция |
| **cookies, выгруженные из браузера телефона** | **25 из 25** — станция воспроизведена точно |

Отсюда простое правило: **чьи cookies — того и микс**. Хочешь скачивать ровно
то, что видишь в своём браузере — принеси его cookies:

#### Одним тапом: расширение для Kiwi

```bash
python main.py kiwi        # соберёт .zip в «Загрузки»
```

В Kiwi: **⋮ → Extensions → Developer mode → «+ (from .zip/.crx/.user.js)»** →
выбери файл. Дальше при запущенной качалке открой YouTube и **тапни иконку
расширения** — cookies уедут сами, вводить ничего не надо.

Почему именно расширение, а не закладка: главные cookies (`SID`, `__Secure-*`)
помечены `httpOnly` и из скрипта на странице не видны **вообще**. Прочитать их
может только `chrome.cookies`, то есть расширение. Забрать базу браузера снаружи
тоже нельзя — каталог приложения Android закрыт без root.

Kiwi назван потому, что он самый известный, но к нему ничего не привязано:
манифест уже **MV3**, так что подойдёт любой Chromium-браузер под Android с
поддержкой расширений. А если браузер с расширениями недоступен вовсе, остаётся
путь файлом (ниже) — он не требует ни расширений, ни конкретного браузера.

Приём защищён четырьмя замками, потому что тут отдают доступ к аккаунту:

| замок | что отсекает |
|---|---|
| `Host` обязан быть `127.0.0.1`/`localhost` | DNS-rebinding: домен с A-записью на `127.0.0.1` |
| origin обязан быть `chrome-extension://` | обычные веб-страницы (у них origin `http`/`https`) |
| `Content-Type: application/json` + заголовок с токеном | «простые» запросы и формы — оба требуют preflight, а его даём только расширению |
| токен из `.api-token` | **чужое расширение** в том же браузере — токен зашивается в `.zip` при `python main.py kiwi`, взять его больше негде |

Остальные POST-эндпоинты (`/api/add`, `/api/start`, `/api/settings`,
`/api/remove`, `/api/check`) принимают команды **только от своей же страницы**:
проверяется `Origin`, а при его отсутствии — `Sec-Fetch-Site`. Без этого любой
открытый сайт мог бы поставить тебе загрузку в очередь и запустить её: с
`Content-Type: text/plain` запрос считается «простым», preflight не
спрашивается, и он бы дошёл — прочитать ответ сайт не смог бы, а действие уже
произошло.

Пересборка расширения **ничего не ломает**: `python main.py kiwi` берёт токен из
существующего `.api-token`, а не выписывает новый, — так что переустанавливать
`.zip` в Kiwi после каждой сборки не нужно. И наоборот, если файл удалить, токен
выпишется заново: тогда `.zip` пересобрать и переустановить придётся, иначе
расширение получит «Качалка не признала расширение». Перезапускать сервер при
этом не надо — он читает `.api-token` на каждый запрос (проверено подменой файла
у живого сервера: старый токен сразу стал давать 403, новый — 200).

#### Или руками, файлом

```bash
python main.py cookies                    # найдёт свежий файл в «Загрузках»
python main.py cookies /путь/к/cookies.txt
```

Выгрузить его можно любым расширением экспорта cookies (формат **Netscape**, не
JSON). Команда проверит файл до замены: формат, наличие строк, маркеры входа —
и откажет с внятной причиной, если что-то не так.

Дальше всё сходится само: yt-dlp с этими cookies воспроизводит станцию твоего
браузера, никакой Chromium для этого не нужен.

### Когда сессия истечёт

Приложение **не притворяется**, что умеет продлевать чужую сессию. Продлить её
без её же браузера нельзя: ключевой `__Secure-1PSIDTS` прокручивает Google в
ответ именно браузеру. Вместо этого — честная проверка:

```bash
python main.py check     # ✓ сессия жива  /  ⚠ истекла
```

Один `GET` к YouTube с твоими cookies и маркер `LOGGED_IN` в ответе. Тот же
запрос делает Web-UI перед началом загрузки и по кнопке «Проверить сессию» в ⚙.
Это **не** замена продлению, а то, чего раньше не было вовсе: прежняя логика
гадала по возрасту файла («меньше 12 часов — значит хорошо»), поэтому молчала,
когда cookies уже мертвы, и тревожила, когда они живы.

Проверка различает **три** исхода, а не два: вход есть, входа нет, и «YouTube
ответил не тем» (консент, капча, сменилась разметка). Последнее не выдаётся за
«сессия мертва» — иначе человек шёл бы заново выгружать рабочие cookies.

Истекла — лечится **одним тапом**: открой YouTube в Kiwi и тапни иконку
расширения. Индикатор в ⚙ станет зелёным сам.

### Зафиксировать конкретную выдачу навсегда

Список поимённо нужен, когда хочется сохранить **именно эту** очередь — скачать
её же через месяц, или перенести выдачу с другого устройства. Вставь список
видео вместо ссылки, по одному в строке (или через запятую) — годятся и голые
ID, и ссылки:

```
cmlCuzn_mqI
https://youtu.be/1TzYnfcxNNE
https://www.youtube.com/watch?v=z3OKd5b2Rlw
```

Скачается **ровно это и ровно в таком порядке** — нумерация файлов пойдёт по
твоему списку, а не по тому, что YouTube выдаст в момент запроса.

#### Сначала проверь cookies — часто список расходится именно из-за них

Микс ведёт себя по-разному в двух режимах:

- **без авторизации** — чистое радио от «сида»: каждый запрос даёт новую
  выдачу. Проверено: два одинаковых запроса подряд с одной машины → 19 общих
  треков из 25 и другой порядок;
- **под аккаунтом** — персональный микс, и он **стабилен**: приложение и сайт
  на одном устройстве показывают одно и то же.

Отсюда практическое правило: **если качалка выдала не то, что видно на
телефоне — скорее всего она ходила анонимно**, а не «микс изменился». Проверь:

```bash
cd ~/4K_video_downloader      # или туда, куда клонировал
yt-dlp --cookies cookies.txt --flat-playlist --playlist-end 25 --print "%(id)s" "<ссылка>"
```

Запусти дважды. Одинаково — cookies работают, и приложение получит ровно то же,
что телефон. Разное — cookies не подхватились (`python main.py check` скажет,
жива ли сессия).

А расхождение **ПК против телефона** обычно значит, что там разные аккаунты или
ПК вообще не авторизован — микс персональный, у каждого аккаунта свой.

#### Как снять очередь вручную — если нужно

Нужно **редко**: только чтобы зафиксировать конкретную выдачу навсегда или когда
устройства принципиально не сходятся. Обычный путь — cookies из расширения, и
руками там делать нечего. Разверни, если этот случай твой:

<details>
<summary>Сниппеты для консоли и закладки (ПК и телефон)</summary>

Сниппеты **не зависят от вёрстки**: они не ищут конкретные теги YouTube (они
разные на десктопе и на мобильном), а собирают ссылки с параметром `index=` — он
есть у элементов очереди и отсутствует у рекомендаций сбоку. Поэтому работают и
на `youtube.com`, и на `m.youtube.com`.

**На ПК — консоль (Chrome → F12 → Console, при открытом миксе)**

```js
(() => {
  const rows = [];
  document.querySelectorAll('a[href*="index="]').forEach(a => {
    const u = new URL(a.href, location.origin);
    const v = u.searchParams.get('v');
    const i = parseInt(u.searchParams.get('index'), 10);
    if (v && i > 0) rows.push({ i, v });       // порядок из index=, а не из вёрстки
  });
  rows.sort((a, b) => a.i - b.i);
  const ids = [];
  rows.forEach(r => { if (ids.indexOf(r.v) < 0) ids.push(r.v); });
  if (!ids.length) return console.log('очередь не найдена — разверни список «Далее»');
  copy(ids.join('\n'));                        // в буфер уходят ТОЛЬКО id
  console.log('снято треков:', ids.length, ids);
})()
```

Число в консоли сверь с длиной очереди. В буфер уходят **только id**, по одному
в строке — именно это и ждёт приложение.

**Закладка — работает и на ПК, и на телефоне**

Нужна, если консоль недоступна (на телефоне её нет вовсе) или Chrome требует
напечатать «разрешить вставку», а кириллической раскладки нет. В поле адреса
закладки вставка не блокируется.

```
javascript:(()=>{const r=[];document.querySelectorAll('a[href*="index="]').forEach(a=>{const u=new URL(a.href,location.origin);const v=u.searchParams.get('v'),i=parseInt(u.searchParams.get('index'),10);if(v&&i>0)r.push([i,v])});r.sort((a,b)=>a[0]-b[0]);const ids=[];r.forEach(x=>{if(ids.indexOf(x[1])<0)ids.push(x[1])});if(!ids.length){alert('Очередь не найдена. Открой микс и разверни список «Далее».');return}prompt('Треков: '+ids.length+'. Скопируй всё:',ids.join(','))})()
```

Селекторы без `#` намеренно: решётка в адресе закладки обрезала бы код как якорь.
Результат отдаётся через `prompt()`, потому что `copy()` существует только в
консоли DevTools.

**На ПК:** правый клик по панели закладок → «Добавить страницу» → в URL вставь
код → назови «Снять очередь». Открой микс → нажми закладку → Ctrl+C.

**На телефоне (Chrome для Android):**

1. открой любую страницу → **★** в меню (закладка создана);
2. меню **⋮ → Закладки**, найди её, тапни **карандаш**;
3. имя — короткое, например `qq`; в поле URL вставь код целиком;
4. открой микс, **разверни список «Далее»** и пролистай его до конца — Chrome
   держит в DOM только отрисованное;
5. тапни адресную строку, набери `qq`, выбери закладку из подсказок — она
   выполнится на открытой странице;
6. в окошке — готовый список через запятую. Скопируй и вставь в приложение.

Если Chrome откажется выполнять закладку из адресной строки (в разных версиях
по-разному), есть два обхода: меню **⋮ → «Версия для ПК»** — вёрстка станет
десктопной, а сниппет и так от неё не зависит; либо поставить **Kiwi Browser**
— это Chromium с настоящими DevTools на Android (меню → Developer tools),
там работает и консольный вариант.

`wake-lock`) и открывает браузер.

## Чего здесь нет и почему

Проект прошёл через попытку держать **свой** браузер: `proot-distro` + Debian +
ARM-Chromium + Playwright, вход в Google через окно на Termux:X11, headless-
обновление cookies, снятие очереди микса из DOM. Это работало. Это вырезано
целиком — вместе с `auth/mix.py`, `auth/login.py`, `auth/bridge.py`,
`scripts/login*.sh`, `scripts/setup-debian.sh`, `scripts/start-x11.sh` и флагом
`--with-browser`.

Причина не в весе, а в том, что слой **проигрывал по своей же задаче**:

| | свой Chromium (~2 ГБ) | расширение для Kiwi (0 МБ) |
|---|---|---|
| совпадение состава My Mix | **2 из 25** | **25 из 25** |
| разбор микса | 30–60 с (старт proot + DOM) | пара секунд |
| установка | десятки минут | один тап |
| процессов в дереве Termux | +proot, +Chromium | нет |

Состав RD-станции определяется идентичностью сессии в cookies — значит нужен
именно тот браузер, где ты смотришь миксы. Свой браузер по определению давал
чужую станцию, и весь слой существовал, чтобы обходить проблему, которую сам же
и создавал. Снятие очереди из DOM было лечением симптома.

Что ушло вместе с ним:

- **риск Android OOM / phantom process killer.** Осталось: python-сервер + до 4
  `ffmpeg` + до 4 `deno` (yt-dlp работает **библиотекой** в потоках, а не
  процессами) — порядка 10 процессов против лимита 32. Chromium в proot был
  единственным, кто реально ел память;
- **хрупкость к вёрстке YouTube.** Парсить DOM больше не нужно вообще;
- **~800 строк кода** и второе окружение, которое надо было отдельно
  устанавливать, обновлять и диагностировать.

Что осталось умышленно:

- **JS-рантайм** — его требует сам yt-dlp для n-challenge (EJS). Не привязан к
  `deno`: yt-dlp поддерживает `deno` > `node` > `quickjs` > `bun` и берёт первый
  доступный, а разрешены все четыре (`config.JS_RUNTIMES`). Самый лёгкий вариант
  — `quickjs-ng`, ~1.5 МБ против ~93 МБ у deno;
- **анимации Web-UI** — CSS-трансформы `transform`/`opacity` (композитор, не
  CPU), обновления состояния схлопнуты в один `requestAnimationFrame`,
  `prefers-reduced-motion` обработан. Проверено на **Helio G88 / 4 ГБ**.

## Аккаунт: как это устроено теперь

Вход живёт **в браузере телефона**. Внутри приложения кнопки «войти» нет
намеренно — её нечем реализовать без своего браузера, а он проигрывает
расширению (см. выше).

1. `python main.py kiwi` → поставить `.zip` в Kiwi;
2. открыть YouTube в Kiwi → тапнуть иконку расширения;
3. всё. Индикатор в ⚙ зеленеет, миксы совпадают с этим браузером.

Перед каждой загрузкой качалка спрашивает YouTube, жива ли сессия (не чаще, чем
раз в `config.COOKIES_MAX_AGE_HOURS`, по умолчанию 12 ч — результат кешируется в
`.cookies-state`). Умерла — скажет прямо и подскажет тот самый один тап. Ни
окна, ни второго окружения, ни команды.

## Web-UI «как приложение» (один тап, без команд)

Лёгкий локальный интерфейс на **stdlib** (`http.server`, **ноль зависимостей** —
тянет даже слабые/старые телефоны). Рисует браузер телефона; сервер слушает
**строго `127.0.0.1`** — 100% on-device, наружу не доступен.

```bash
python main.py web      # поднимет сервер и сам откроет браузер
```

**Возможности:**
- 📋 **Вставка плейлиста из буфера** одним тапом → `probe` → карточка в очереди.
- 🗂 **Очередь до 5 My Mix**; тап по миксу → экран **деталей** с потреково.
- 🎨 **Качество ②** — 3 реальных потока YouTube, цвет по уровню:
  🔵 **Максимум** (Opus ~160k) · 🟢 **Стандарт** (AAC 128k) · ⚪ **Эконом** (~50–64k).
- 🏷 **Платформа ①** — бренд-цвета из логотипов (iOS=графит, Win=синий,
  Android=зелёный, Linux=янтарь); задаёт контейнер/кодек.
- 🎚 **Слайдер параллелизма** с цветовым риском 🟢→🔴; метка и риск считаются
  по факту (см. «Параллелизм» ниже).
- 📈 **Карточка «созревает»**: рамка перетекает синий → зелёный по мере %,
  свечение растёт; готово → зелёный, ошибка → красный.
- 🎛 **Дизайн-система «прибор»**: hi-fi-эстетика по миру предмета — mono-шрифт
  как голос устройства (нейм-плейт, лейблы с хвостовой линейкой, цифры, лог),
  **сегментные метры** прогресса вместо гладких полосок, тик-линейка под шапкой,
  **LED связи** в нейм-плейте (реальное состояние SSE: зелёный — связь живая).
  Никаких эмодзи в UI — только текстовые глифы и SVG (эмодзи на каждом
  телефоне рисуются по-своему).
- 🍎 **Механика iOS**: GPU-анимации (`transform: scaleX`), пружинный easing,
  сегмент-контрол с **тапом И drag-ом** (тянешь палец, на краях — резина),
  тактильные тапы. Прогресс «доплавляется» CSS между throttle-апдейтами.
  Лист настроек закрывается свайпом вниз за полоску, карточки уезжают мягко,
  бар активной загрузки бликует, статусы ⟳ крутятся — всё на transform/opacity.
- 📱 **Совместимость — почти любой смартфон**, не только S23 Ultra:
  Chrome/WebView ~80+, Samsung Internet, Firefox для Android; экраны от 320px
  до планшета/десктопа (на широком — колонка по центру, лист становится
  диалогом); вырезы/чёлки (safe-area); слайдер стилизован и под Firefox;
  системное «уменьшить движение» отключает анимации; иконки — SVG, а не эмодзи
  (эмодзи на каждом телефоне рисуются по-своему).
- 🏠 **«Как приложение» буквально**: manifest + иконка. Меню браузера →
  «Добавить на главный экран» → отдельное окно без адресной строки
  (standalone). Сервер по-прежнему поднимает виджет Termux:Widget.
- 🔁 Загрузка **переживает закрытие вкладки** (состояние держит сервер, SSE).
- 🔑 **Cookies приезжают в UI сами** из расширения в Kiwi; в ⚙ два индикатора
  (жива ли сессия / под аккаунтом ли качаем) и кнопка «Проверить сессию» — один
  `GET` к YouTube, без браузера и без второго окружения.

### Параллелизм и анти-бан

Слайдер = **бюджет потоков** (потолок риска). Бюджет **делится по реально
добавленным миксам**, потолок одного плейлиста — **4 потока** (проверенный 4KVD):

```
1 микс,  слайдер 6  →  1 плейлист × 4 трека = 4 потока   (один My Mix = 4)
2 микса, слайдер 6  →  2 × 3 = 6
3 микса, слайдер 6  →  3 × 2 = 6
```
Плюс человеческий темп: ramp-up/джиттер старта треков (`config.START_JITTER_MAX`)
и пауза 2–12с после полностью скачанного My Mix
(`config.PLAYLIST_PAUSE_MIN/MAX`). Суммарно потоков **не больше слайдера**.

## Обновление

```bash
cd ~/4K_video_downloader      # или туда, куда клонировал
git pull
bash scripts/doctor.sh         # чего не хватает после обновления
```

Имя папки нигде не зашито: все скрипты находят корень проекта через
`readlink -f "$0"`, поэтому клонировать можно куда угодно и под любым именем —
ярлык в `~/.shortcuts` продолжит работать даже через симлинк.

### Код обновился, а зависимости — нет

`git pull` приносит **только код**. Пакеты и Python-модули остаются от прошлой
установки, и если новый код рассчитывает на что-то новое, это вылезет невнятной
ошибкой где-нибудь в середине работы.

Чтобы такого не было, у набора зависимостей есть **версия**
(`config.SETUP_VERSION`). Установщик записывает её в `.setup-stamp`, а программа
при запуске сверяет — и если окружение отстало, честно об этом говорит:

```
⚠  код новее окружения (зависимости v2, нужна v3) — обнови: bash scripts/setup-termux.sh
```

> **Обновляешься с версии с браузер-слоем?** Он больше не нужен — освободи ~2 ГБ:
> ```bash
> proot-distro remove debian
> pkg uninstall proot-distro termux-x11-nightly termux-am
> rm -rf auth/profile .cookies-external
> bash scripts/setup-termux.sh
> ```
> Cookies при этом никуда не денутся, но вход теперь идёт через расширение в
> Kiwi (`python main.py kiwi`).

Та же строка появляется в Web-UI (⚙ → сверху жёлтым). Лечится повторным запуском
установщика — он **идемпотентный**, уже поставленное не ломает и не переставляет:

```bash
bash scripts/setup-termux.sh
```

**Отдельно про yt-dlp:** YouTube ломает совместимость чаще всего именно там, и
это не связано с версией набора. Если посыпались ошибки форматов — первым делом
`pip install -U yt-dlp`.

### Диагностика

```bash
bash scripts/doctor.sh          # полная проверка (спрашивает YouTube про сессию)
bash scripts/doctor.sh --quick  # без обращения к сети
```

Проверяет пакеты Termux, Python-модули (и печатает версию yt-dlp), наличие APK,
доступ к памяти, версию окружения и **жива ли сессия** — не «есть ли файл
cookies», а узнаёт ли нас YouTube. Для каждой проблемы печатает готовую команду.
Код возврата `0` — всё на месте, `1` — есть чего чинить.

## Если что-то пошло не так

> Быстрее всего начать с `bash scripts/doctor.sh` — он проверит всё разом и
> напечатает готовые команды. Таблица ниже — для случаев, где нужна причина.

| Симптом | Причина и лечение |
|---|---|
| В миксе не те треки, что в приложении YouTube | Почти всегда — качалка ходила анонимно. `python main.py check`: если сессия мертва, открой YouTube в Kiwi и тапни иконку расширения. RD-микс привязан к сессии, поэтому нужны cookies **того** браузера, где ты смотришь микс. Не сходится и с ними — вставь список видео вручную |
| `python main.py check` говорит «истекла», хотя в браузере всё открыто | Google прокрутил токены после экспорта. Один тап по расширению — и cookies снова совпадают с браузером |
| «YouTube ответил незнакомой страницей» | Проверка сознательно **не** выносит приговор cookies: так отвечает консент-страница, капча или смена разметки. Cookies при этом обычно рабочие — просто качай |
| Странная ошибка после `git pull`; «у друга не работает» | Окружение отстало от кода: пакеты `git pull` не обновляет. `bash scripts/doctor.sh`, затем `bash scripts/setup-termux.sh` (он идемпотентный) |
| `Sign in to confirm you're not a bot` / форматы пропали и после обновления | Похоже на гейт **PO-token** (Botguard): YouTube требует его для части клиентов, и JS-рантайма для этого мало — нужен плагин-провайдер PO-token (`bgutil-ytdlp-pot-provider` и подобные). Сначала всё равно `pip install -U yt-dlp`: обычно гейт снимают в самом yt-dlp быстрее, чем успеваешь ставить плагины. `doctor.sh` подсказывает, если версия старше 30 дней |
| `Only images are available` / `Requested format is not available` | Сначала `pip install -U yt-dlp` и проверь JS-рантайм (`pkg install deno` — первый запуск качает решатель EJS, нужен интернет). Если не помогло, сравни: `yt-dlp -F <URL>` против `yt-dlp --extractor-args "youtube:player_client=…" -F <URL>`. Когда форматы есть только без `player_client` — значит пин клиентов в `config.YOUTUBE_PLAYER_CLIENTS` протух, верни `[]` (yt-dlp выберет сам). Именно это и случилось с `tv,ios,web_safari`: DRM-эксперимент на tv + PO-token на ios |
| Расширение не отдаёт cookies | Качалка должна быть запущена (`python main.py web`) — расширение стучится на `127.0.0.1:8765`. И экспортируй с открытой страницы `youtube.com`, где ты авторизован |
| Файл-экспорт отвергнут: «это JSON» | В расширении-экспортёре выбери формат **Netscape**, не JSON |
| `cookies.txt нет` / «вход не выполнен» | `python main.py kiwi` → поставить расширение в Kiwi → тапнуть иконку |
| Загрузка обрывается при гаснущем экране | Doze. Отключи оптимизацию батареи для Termux (см. «Требования») |
| Samsung Music не видит треки | Нужны и пакет `termux-api`, и APK **Termux:API** — одного `termux-setup-storage` не хватает. Проверь: `termux-media-scan -v <файл>` (должен напечатать путь, а не молчать). Молчит — сними ограничения батареи и с **Termux:API** тоже, иначе Android глушит его в фоне и сканер сбоит без ошибки |
| Расширение говорит «Качалка не признала расширение» | Токен разошёлся: пересобери и переустанови `.zip` — `python main.py kiwi` |
| Осталось ~2 ГБ от старого браузер-слоя | Он больше не используется — как снести, см. «Обновление» |
